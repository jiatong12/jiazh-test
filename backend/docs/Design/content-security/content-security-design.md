# 内容加密展示 功能设计

## 1. 背景与目标
- 业务背景：面向内容安全场景，需要对文字内容进行加密存储，在页面上通过自定义字体安全展示，防止内容被直接复制泄露。
- 目标：
  - 实现文字内容的加密存储与安全管理
  - 通过字库混淆技术实现页面正常展示
  - 前端限制直接复制
  - 不影响内容的检索查询

## 2. 范围
### 2.1 本次范围
- 加密内容管理（新增、编辑、删除、查询、详情查看）
- 内容分类管理（新增、编辑、删除、查询）
- 字库混淆加密与解密（基于字符映射表）
- 自定义字体文件生成与下载
- 前端加密内容展示（加载自定义字体）
- 前端复制限制（CSS + JS）
- 内容检索查询（基于原文搜索）

### 2.2 非本次范围
- 字库动态在线生成（本次使用预置映射表 + 静态字体文件）
- 多套字体映射方案切换
- 内容审批流程
- 内容导出

## 3. 角色与参与方
| 角色 | 说明 | 主要操作 |
| --- | --- | --- |
| 管理员 | 内容管理人员 | 新增/编辑/删除内容、管理分类、查看内容 |
| 访客 | 前端查看者 | 查看加密展示内容，无法直接复制 |

## 4. 技术方案

### 4.1 字库混淆原理
1. 维护一份**字符映射表**，将常用汉字/字符映射为另一组字符（如 `你→丂`、`好→乂`）
2. 内容保存时，后端根据映射表将原文逐字替换，生成**加密内容**存入数据库
3. 同时保留**原文内容**用于检索
4. 生成一个自定义字体文件（TTF/WOFF），其中加密字符的字形（glyph）绘制为对应原文的形态
5. 前端展示加密内容时，加载该自定义字体，使加密字符在视觉上呈现为原文
6. 用户尝试复制时，复制的是加密后的字符（乱码），而非原文

### 4.2 加密流程
1. 用户在前端输入原文内容
2. 前端将原文发送至后端保存接口
3. 后端保存时同时存储原文（用于检索）和加密内容（用于展示）
4. 前端展示详情时，获取加密内容并用自定义字体渲染

### 4.3 复制限制方案
- CSS `user-select: none` 禁止选中
- JS 拦截 `copy` 事件，清空剪贴板内容
- 右键菜单禁用（在加密展示区域内）

## 5. 业务流程
### 5.1 主流程
1. 管理员登录系统，进入内容管理
2. 选择分类，新增内容（填写标题、正文）
3. 后端保存原文 + 加密内容
4. 管理员可在列表中搜索、查看内容
5. 前端通过自定义字体展示加密内容，访客无法直接复制

### 5.2 异常流程
1. 分类不存在时，内容无法保存
2. 字体文件加载失败时，展示加密字符（乱码），提示用户刷新

## 6. 业务规则
- 校验规则：标题必填，不超过200字；正文必填
- 状态规则：内容有草稿和已发布两种状态
- ID生成：使用框架 MaxNumberGenerator.generate()
- 访问约束：管理操作需登录，字体文件下载无需登录

## 8. 数据模型
### 8.1 内容表（ZSContent）
| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| ID | LONG | Y | 主键 |
| Title | VARCHAR(200) | Y | 内容标题 |
| OriginalContent | CLOB | Y | 原文内容（用于检索） |
| EncryptedContent | CLOB | Y | 加密内容（用于展示） |
| CategoryID | LONG | N | 分类ID |
| Status | INTEGER | Y | 状态：0草稿，1已发布 |
| AddTime | DATETIME | Y | 增加时间 |
| AddUser | VARCHAR(200) | Y | 增加人 |
| ModifyTime | DATETIME | N | 修改时间 |
| ModifyUser | VARCHAR(200) | N | 修改人 |

| 字段 | 类型 | 必填 | 说明 |

| ID | LONG | Y | 主键 |

| OrderFlag | LONG | N | 排序号 |
| AddTime | DATETIME | Y | 增加时间 |
| AddUser | VARCHAR(200) | Y | 增加人 |
| ModifyTime | DATETIME | N | 修改时间 |
| ModifyUser | VARCHAR(200) | N | 修改人 |
